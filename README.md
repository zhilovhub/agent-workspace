# Agent workspace

Рабочий контекст задач в коротких Markdown-файлах: правила, постановка,
состояние и решения. Подходит для разработки и бытовых дел.

## Начать

Открой эту директорию как проект в Codex или запусти:

```sh
cd ~/agent-workspace
codex
```

Напиши: «Давай начнём задачу: спланировать ремонт кухни».
Агент создаст отдельную папку в projects/, заполнит известное и уточнит неизвестное.

| Фраза | Результат |
| --- | --- |
| Давай начнём задачу… | Папка из шаблона и первоначальный контекст |
| Давай сформулирую задачу и контекст… | Постановка в BRIEF.md и локальные правила |
| Я сделал то-то без тебя | Обновлённый STATE.md с отметкой источника |
| Я восстановил контекст такой-то ревизии | Агент перечитает файлы и сверит их с артефактами |
| Подготовь новый диалог | Актуальный контекст и короткая фраза продолжения |

Версии, коммиты и публикацию ведёшь ты. Набор не выполняет Git-операции
и не создаёт отдельную систему снимков. Чтобы вернуться к ревизии, восстанови
файлы своим способом и попроси агента перечитать контекст.

## Файлы

| Файл | Назначение |
| --- | --- |
| AGENTS.md в корне | Общие правила и стиль |
| SKILLS.md | Краткий каталог переносимых скиллов |
| AGENTS.md задачи | Только локальные особенности |
| BRIEF.md | Цель, контекст, ограничения, критерии готовности |
| STATE.md | Сделано, в работе, следующие шаги, блокеры, продолжение |
| DECISIONS.md | Значимые решения и причины |
| artifacts/ задачи | Код, документы и другие результаты |

Три скилла находятся в .agents/skills/, шаблоны — в templates/task/.
Каталог SKILLS.local.md можно создать для возможностей конкретного устройства.
Его хранение и переносимость определяешь ты.

Обычно достаточно общения с агентом. Для ручного создания задачи есть скрипт
без внешних Python-зависимостей (Python 3.9+):

```sh
python3 scripts/workspace.py new my-task --title "Моя задача"
```

Он создаёт четыре файла и artifacts/, отказывается перезаписывать существующую
задачу. Постановку после создания заполняете вместе с агентом.

## Новый диалог

Агент предлагает переход после крупного этапа, смены подзадачи или накопления
лишнего обсуждения. Это рекомендация, а не датчик заполненности контекстного окна.

Открой новый диалог в корне workspace и напиши:

> Продолжаем projects/my-task. Прочитай действующие AGENTS.md, BRIEF.md
> и STATE.md, сверь их с артефактами и начни с раздела «Продолжение».

Откат файлов не стирает сообщения текущего диалога. После восстановления старого
контекста новый диалог помогает продолжить именно с выбранной постановки.

## Перенос и обнаружение

Переноси весь каталог, включая скрытую .agents/. Способ хранения и синхронизации
выбираешь ты. На другом устройстве нужны Codex и Python для скрипта создания.
Авторизации и установленные программы остаются локальными.

[Codex читает AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
от корня проекта до рабочей директории. Без определённого корня проекта он
проверяет только текущую директорию. Поэтому для независимой папки запускай
Codex из корня workspace; агент прочитает контекст выбранной задачи явно.

[Скиллы](https://learn.chatgpt.com/docs/build-skills) обнаруживаются в .agents/skills.
Проверь task-start, context-sync и context-handoff через /skills в CLI.
Если они не появились, перезапусти Codex. SKILLS.md — каталог, а не регистрация.
Глобальные инструкции устройства продолжают действовать; набор их не меняет.

## Проверка скрипта

```sh
python3 -B -m unittest discover -s tests -v
```

Проверки создают задачи во временных папках.
